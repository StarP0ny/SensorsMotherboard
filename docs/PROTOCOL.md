# SensorsMotherboard — протокол v1

Согласовано 7 октября 2026 года; дополнено 16 октября 2026 года. Прошивка 0.2.0, CH32V303CBT6,
CMake/Ninja/WCH GCC12, `wch_low_level_drivers` на коммите `a87bfa9`.
Основной транспорт USB Full Speed CDC, резервный UART 460800 8N1.

## Первый этап

Реализованы кадры, команды, пинги, синхронизация UTC, TCA9548A,
SCD41/SHT41/SDP810, кнопка и LED автоматического режима, драйвер VisserLab.
Проверка без платы не подтверждает работу USB/I²C на железе.
Назначения датчиков и TCA сохраняются во flash. Автономный журнал и RTC — следующий этап.
Зарезервированные команды журнала возвращают UNSUPPORTED; возможность
журнала в HELLO не объявляется.

## Плата

Назначения в `config/board_config.h`. Кварц 8 МГц, SYSCLK 96 МГц;
кварц 32,768 кГц оставлен для RTC.

| Назначение | Подключение |
|---|---|
| USB D− / D+ | PA11 / PA12; проверить разводку разъёма |
| UART TX / RX | PA9 / PA10, логика 3,3 В |
| I²C1 SCL / SDA | PB6 / PB7, 400 кГц, внешние подтяжки |
| I²C2 SCL / SDA | PB10 / PB11, 400 кГц, внешние подтяжки |
| TCA9548A RESET | PB5, активный низкий |
| TCA9548A адрес | 0x70, A0/A1/A2 на GND |
| SCD41 | канал 0, адрес 0x62, ID 1 |
| SHT41 | канал 1, адрес 0x44, ID 2 |
| SDP810 | I²C2 напрямую, адрес 0x25, ID 3 |
| Кнопка | PB0 → кнопка → GND, внутренняя подтяжка вверх |
| LED автоматического режима | PB1 → резистор → LED → GND |

TCA9548A поддерживает несколько включённых ветвей. Первый драйвер выбирает
одну для каждой транзакции, чтобы изолировать неисправные ветви.
По умолчанию `MUX_ENABLED=0`: SCD41/SHT41 напрямую к PB6/PB7, SDP810 к PB10/PB11,
без обращения к TCA9548A. `SCD_BUS`, `SHT_BUS`, `SDP_BUS` выбирают шину (1/2).
Для начальных ветвей I²C1 установить `MUX_ENABLED=1`; начальные пути I²C2 прямые.
Эти макросы используются только при отсутствии корректной сохранённой топологии.
После CONFIG_SAVE при загрузке применяются сохранённые назначения. Через команды
топологии TCA можно назначить на любую из двух шин без пересборки.
При прямом подключении ENUM передаёт mux_address=0, channel=0xFF.

## Кадр

```text
magic_start | sequence | time | type | length | payload | crc32 | magic_end
```

| Смещение | Поле | Формат |
|---:|---|---|
| 0 | magic_start | `56 53 4C 42`, ASCII VSLB |
| 4 | sequence | uint32 |
| 8 | time | uint64, микросекунды |
| 16 | type | uint16 |
| 18 | length | uint16, длина только payload |
| 20 | payload | length байт |
| 20 + length | crc32 | uint32 |
| 24 + length | magic_end | `42 4C 53 56`, ASCII BLSV |

Little-endian, без padding. Заголовок 20 байт, кадр `28 + length`.
Максимальный payload 1024 байта. Поля сериализуются явно, не packed-структурой.
CRC-32/ISO-HDLC: poly 0x04C11DB7, init 0xFFFFFFFF, refin/refout true,
xorout 0xFFFFFFFF; `123456789` → 0xCBF43926. CRC по sequence…конец payload,
без сигнатур. Подходят библиотечный getCRC32 и Python zlib.crc32.

Сигнатуры внутри payload допустимы. При ошибке длины/CRC/конца парсер
сдвигается на байт и повторяет поиск. Неполный кадр сбрасывается после
250 мс без новых байтов; это ограничение сборки кадра, не связи.
sequence увеличивается на каждый кадр отдельно в каждом направлении,
с переполнением uint32. Ответы начинают payload с request_sequence:uint32.
Живые кадры не ретранслируются. Команды изменения состояния первой версии
идемпотентны. Для будущих неидемпотентных команд потребуется кэш ответов.

## Сообщения

u8/u16/u32/u64 — беззнаковые числа, i64 — знаковое. Длина payload точная.

| type | Имя | Payload |
|---:|---|---|
| 0x0001 | HELLO_REQ | protocol_version:u16 |
| 0x0002 | HELLO | request:u32, protocol:u16, fw_major:u16, fw_minor:u16, fw_patch:u16, max_payload:u16, uid:12 байт, reset_flags:u32, boot_id:u32, capabilities:u32 |
| 0x0010 | ENUM_REQ | пусто |
| 0x0011 | ENUM | request:u32, count:u16, descriptors[count] |
| 0x0020 | GET_CONFIG | object:u16 |
| 0x0021 | SET_CONFIG | object:u16, count:u16, {key:u16,value:u32}[count] |
| 0x0022 | CONFIG | request:u32, object:u16, count:u16, {key:u16,value:u32}[count] |
| 0x0030 | START | count:u16, sensor_id:u16[count]; count=0 — все |
| 0x0031 | STOP | как START |
| 0x0040 | DATA | count:u16, records[count] |
| 0x0041 | STATUS | auto:u8, linked:u8, run_mask:u16, missed_pings:u32, transport_drops:u32, bad_rx_frames:u32, present_mask:u16, reserved:u16 |
| 0x0042 | EVENT | sensor_id:u16, error:u16 (первая версия) |
| 0x0050 | TIME_SYNC_REQ | пусто, time=T1 UTC ПК |
| 0x0051 | TIME_SYNC_RESP | request:u32, T1:u64, M2:u64; time=M3 монотонное |
| 0x0052 | TIME_SYNC_SET | utc_offset_us:i64 |
| 0x0060…0x0064 | LOG_INFO_REQ / LOG_INFO / LOG_READ / LOG_DATA / LOG_ACK | зарезервировано |
| 0x0070 | RESULT | request:u32, code:u16 |
| 0x0080 | PING | пусто |
| 0x0081 | PONG | request:u32 — sequence соответствующего PING |
| 0x0090 | I2C_SCAN_REQ | bus:u8 (1/2), mux_address:u8, channel:u8; mux=0/channel=0xFF — напрямую; иначе TCA 0x70…0x77, канал 0…7 |
| 0x0091 | I2C_SCAN | request:u32, bus:u8, channel:u8, count:u8, addresses:u8[count] |
| 0x00A0 | TOPOLOGY_REQ | пусто |
| 0x00A1 | TOPOLOGY | request:u32, mux_count:u8, {bus:u8,address:u8}[mux_count], sensor_count:u8, assignment[sensor_count] |
| 0x00A2 | SENSOR_ASSIGN | assignment: sensor_id:u16, model:u16, bus:u8, mux_address:u8, channel:u8, address:u8, period_us:u32 |
| 0x00A3 | SENSOR_REMOVE | sensor_id:u16 |
| 0x00A4 | MUX_ASSIGN | bus:u8, address:u8, enabled:u8 (0/1) |
| 0x00A5 | CONFIG_SAVE | пусто |
| 0x00A6 | IDENTIFY_REQ | bus:u8, mux_address:u8, channel:u8, address:u8 |
| 0x00A7 | IDENTIFY | request:u32, bus:u8, mux_address:u8, channel:u8, address:u8, model:u16; model=0 — измерение не подтверждено |

RESULT: 0 OK, 1 BAD_LENGTH, 2 UNSUPPORTED, 3 BAD_VALUE, 4 BUSY, 5 I2C_ERROR,
6 STORAGE_ERROR (не удалось записать или проверить настройки).
Скан проверяет ACK адресов 0x08…0x77 без записи данных, по одному адресу
за проход основного цикла; пинги и опрос продолжаются. NACK — адрес отсутствует,
ошибка шины/мультиплексора — RESULT I2C_ERROR. Параллельный скан возвращает BUSY.
Допустимый путь определяется текущими назначениями TCA; остальные возвращают BAD_VALUE.
Однобайтный старый запрос channel сохраняет прежний формат ответа и сканирует I²C1.
Двухбайтный запрос bus/channel также поддерживается: channel=255 — напрямую,
иначе используется MUX_ADDRESS. Ответ скана не содержит адрес TCA; принадлежность
определяется request_sequence исходного запроса.
VisserLab сканирует обе шины напрямую и все восемь ветвей каждого назначенного TCA.
Ошибка одного пути не препятствует проверке остальных; показывается отдельно.
Подсказка модели по адресу не заменяет проверку датчика чтением измерения.
Sensor error: 1 I²C/таймаут, 2 CRC, 3 NOT_READY зарезервирован;
нормальное ожидание SCD41 не считается ошибкой.
Capabilities: bit0 — опрос, bit1 — синхронизация, bit2 — журнал (пока 0),
bit3 — сохранённая топология и диагностика подключений.
boot_id диагностический, уникальность при потере питания пока не гарантируется.
Перезапуск определяется новым HELLO, сбросом sequence и монотонного времени.

ENUM descriptor (16 байт): sensor_id:u16, model:u16, bus:u8, mux_address:u8,
channel:u8, address:u8, period_us:u32, present:u16, reserved:u16.
model: 1 SCD41, 2 SHT41, 3 SDP810.
ENUM показывает настроенные пути, present=1 после корректного измерения.
Это не сканирование произвольных неизвестных устройств.

### Назначения и сохранение

Assignment занимает 12 байт; в TOPOLOGY и SENSOR_ASSIGN используется один формат.
ID 1…16 произвольны и не определяют модель. Физический путь датчика уникален.
При прямом подключении mux_address=0, channel=255; для TCA путь должен быть
предварительно добавлен MUX_ASSIGN. TCA с назначенными датчиками удалить нельзя.
При удалении TCA сначала записывается нулевая маска каналов; если запись
не удалась, возвращается I2C_ERROR, назначение TCA сохраняется.

SENSOR_ASSIGN/REMOVE, MUX_ASSIGN и CONFIG_SAVE доступны только без опроса,
сканирования и определения модели; иначе BUSY. Изменения сначала применяются
в RAM. CONFIG_SAVE сохраняет топологию и периоды датчиков, проверяет чтением;
повторное сохранение неизменных данных не пишет flash. Настройки пингов,
передачи и синхронизации остаются в RAM. После перезапуска восстанавливается
последняя корректная запись, при её отсутствии используются board_config.h.

Снимок топологии: 232 байта, magic:u32=0x32504F54, маски TCA на шинах 1/2
по одному байту, два резервных нулевых байта, 16 assignment по 12 байт,
32 резервных нулевых байта. Неиспользованный слот заполнен нулями. Версия
формата задаётся magic; CRC и размещением записей управляет config_store.

IDENTIFY_REQ выполняет пробный цикл измерения с проверкой CRC. Адрес выбирает
поддерживаемое семейство, успешное измерение подтверждает model=1/2/3;
другие адреса или ошибка/таймаут дают model=0. Проба не создаёт назначение.
До её завершения нельзя начинать другой скан или менять топологию.
VisserLab освобождает конфликтующие назначения перед миграцией, сохраняет
результат после применения всех изменений и пытается восстановить прежние
назначения при ошибке. Несвязанные назначения платы сохраняются.

DATA record: sensor_id:u16, time_offset_us:u32, data_length:u16, data.
Время заголовка — самый ранний отсчёт. Остальные — time+time_offset_us.
При коррекции UTC пачка закрывается. data — исходные слова u16:

- SCD41: CO₂, T, RH (6 байт). CO₂ ppm; T=`−45+175*raw/65535` °C;
  RH=`100*raw/65535` %.
- SHT41: T, RH (4 байта). T=`−45+175*raw/65535`; RH=`−6+125*raw/65535`,
  на ПК ограничивается 0…100.
- SDP810: DP, T, scale (6 байт). DP и T интерпретируются как int16;
  давление `DP/scale` Па, температура `T/200` °C. Scale читается из датчика,
  60 для ±500 Па, 240 для ±125 Па; нулевой scale отвергается.

SDP810: непрерывный режим `0x3615`, усреднение до чтения и компенсация
перепада давления; период чтения 100 мс. При старте stop `0x3FF9`, ожидание
1 мс, start, ожидание 20 мс. При STOP датчик останавливается; после ошибки
повторный запуск через 1 с. После включения питания выдерживается 25 мс.

SCD41 periodic 5 с, data_ready, CRC каждого слова. При старте stop+500 мс,
ASC выключается без записи EEPROM, затем start_periodic. SHT41: 0xFD,
ожидание 10 мс, период по умолчанию 1 с. Метка — завершение чтения,
не начало преобразования. CRC-8 Sensirion: poly 0x31, init 0xFF, без отражения.

## Время

ПК → МК: UTC отправки, микросекунды от 2000-01-01 00:00:00 UTC.
МК → ПК: до синхронизации время с запуска, после UTC; TIME_SYNC_RESP
всегда содержит монотонное M3. time < 631152000000000 (начало 2020)
означает монотонное время. UTC до 2020 не поддерживается.
Внутренний таймер не переставляется, меняется поправка передаваемого времени.

```text
T1 = ПК отправил запрос
M2 = МК разобрал запрос
M3 = МК сформировал ответ
T4 = ПК разобрал ответ
round_trip = (T4 - T1) - (M3 - M2)
utc_offset = ((T1 - M2) + (T4 - M3)) / 2
UTC(m) = m + utc_offset
```

ПК выбирает минимальный RTT из серии обменов, отправляет TIME_SYNC_SET.
Метки программные: задержки USB/ОС/очередей входят в погрешность; оценка
предполагает симметричную задержку. Точность проверяется на плате.
TIME_SYNC_SET подтверждается RESULT уже с новым UTC.
Разница с Unix epoch 946684800 секунд, правила счёта как у Unix time.

## Пинги, настройки и автоматический режим

HELLO начинает сессию. МК отправляет PING каждые ping_ms (default 1000).
ПК немедленно отвечает PONG. На следующем сроке отсутствие PONG увеличивает
счётчик пропусков; при missed_limit (default 1) связь потеряна. Дополнительного
таймаута перехода нет. Пинги продолжаются без DATA. Входящий PING также
получает PONG. Один управляющий порт; второй получает BUSY до потери первого.

object=0:

| key | Настройка | Диапазон / default |
|---:|---|---|
| 1 | ping_ms | 100…60000 / 1000 |
| 2 | missed_limit | 1…100 / 1 |
| 3 | tx_interval_us | 0…1000000 / 0; 0 — сразу после измерения |
| 4 | sync_interval_ms | 0 или 1000…3600000 / 30000; исполняется ПК |

object=1…16: ID настроенного датчика, key=16 — period_us, минимум 5000000
для SCD41 и 10000 для SHT41/SDP810, максимум 60000000. Периоды сохраняются
вместе с топологией по CONFIG_SAVE; без него изменения действуют только до перезапуска.
Интервал передачи не меняет частоту измерений; заполненная пачка отправляется
досрочно. Два места TX-очереди зарезервированы для управления.

При включении платы автоматический режим выключен. Нисходящий фронт PB0
после 30 мс стабильного нажатия переключает режим. Удержание/отпускание
не переключают. PB1 горит при включённом режиме. Автоматический режим
опрашивает все три датчика независимо от ПК. START/STOP управляют отдельным
запросом ПК; STOP не выключает физический автоматический режим.
После потери пингов опрос продолжается только при включённом автомоде.

## Журнал — согласовано для следующего этапа

При потере ПК и включённом автоматическом режиме уменьшаем частоту и
сохраняем начало отключения. Журнал линейный: при заполнении прекращаем
запись, ничего не перезаписываем, опрос продолжается.
После возвращения ПК обычная частота, живые данные и фоновая выгрузка.
Освобождение данных только после подтверждения сохранения на ПК.
Нужно выбрать частоты, формат блоков и правила нескольких отключений.
CH32V303CB: 128 КиБ zero-wait, 352 КиБ non-zero-wait, суммарно 480 КиБ.
Первый этап: прошивка в zero-wait, большая область оставлена под журнал.
Zero-wait не означает мгновенное программирование flash.
