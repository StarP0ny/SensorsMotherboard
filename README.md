# SensorsMotherboard

Шлюз CH32V303CBT6 → USB CDC / UART → VisserLab. Первый этап: бинарный
протокол, пинги, синхронизация UTC, TCA9548A, SCD41 и SHT41.

[Протокол, подключения и согласованные решения](docs/PROTOCOL.md).

## Сборка

```powershell
git submodule update --init --recursive
cmake --preset firmware
cmake --build --preset firmware
```

По умолчанию SDK берётся из `%USERPROFILE%/Documents/Welrok/wk-sdk`.
Другой путь можно задать переменной окружения `WK_SDK_PATH` или аргументом
`cmake --preset firmware -DWK_SDK_PATH=...`. Результаты в
`build/firmware/firmware.elf`, `.hex`, `.bin`. Нужны CMake ≥3.21, Ninja,
WCH RISCV_GCC12 из Welrok SDK. Локальные пути к ktz не нужны.

GPIO/каналы: `config/board_config.h`. До проверки USB-разъёма можно
использовать UART PA9/PA10 с адаптером 3,3 В.
После включения опрос запускается кнопкой PB0 либо START от ПК.
PB1 показывает автоматический режим. Первый отсчёт SCD41 примерно
через 6 с, SHT41 через 10 мс после запуска.

В соседнем VisserLab добавлены драйверы `vgw`, `scd41`, `sht41`.
Пример стенда: `examples/devices.yaml`, заменить COM-порт.
Запуск из VisserLab: `python -m visserlab --config ../SensorsMotherboard/examples collect`.

## Прошивка через WCH-Link

Из каталога SensorsMotherboard после сборки:

```powershell
cmake --build --preset firmware --target flash
```

В VS Code: **Terminal → Run Task → SensorsMotherboard: flash (WCH-Link)**.
Задача сначала настраивает и собирает прошивку, затем записывает ELF,
проверяет запись и перезапускает плату. Требуется подключённый WCH-Link.
Для сборки без записи есть задача **SensorsMotherboard: build**.

На текущем стенде проверены запись с верификацией, USB CDC (COM27), HELLO,
ENUM, START/STOP, пинги и синхронизация UTC. За 12 секунд обмена потерь
кадров не обнаружено. COM3 относится к UART WCH-Link; ответа прошивки
через него пока нет. Опрос SCD41/SHT41 возвращает ошибки I²C — реальные
измерения ещё не проверены.

## Проверка без платы

```powershell
python -m pytest tests -q
```

Нужен нативный GCC (MinGW) либо переменная HOST_CC с его путём.
Тесты сверяют C/Python кадры и выполняют код прошивки с подменённой периферией.
Сборка и тесты не заменяют проверку USB/I²C на плате.
Назначения подключений и периоды датчиков сохраняются во flash; журнал и RTC — следующий этап.

## SDP810 и прямое подключение I²C

По умолчанию `MUX_ENABLED=0` в `config/board_config.h`: все датчики подключаются
напрямую, без TCA9548A. SDP810 по умолчанию на I²C2: SCL → PB10, SDA → PB11, VDD → 3,3 В,
GND → GND. Для SDP8xx Digital выводы: 1 SCL, 2 VDD, 3 GND, 4 SDA;
ориентацию проверять по виду снизу в `docs/SDP8xx.pdf`.
SCL и SDA требуют внешних подтяжек к 3,3 В (например, 4,7 кОм для коротких
проводов; учитывать уже установленные на модуле). Частота шины 400 кГц.

SDP810 имеет ID/model 3, адрес `SDP_ADDRESS=0x25`, период чтения 100 мс.
Поддерживаются варианты ±125/±500 Па: коэффициент пересчёта читается из датчика.
Непрерывный режим `0x3615`: компенсация перепада давления, усреднение до чтения.
Первый отсчёт через 20 мс после старта; CRC проверяется для каждого слова.
VisserLab: драйвер `sdp810`, каналы `dp` (Па) и `t` (°C), пример в
`examples/devices.yaml`. Опрос запускается START либо кнопкой PB0.

Для подключения через TCA9548A установить `MUX_ENABLED=1` и пересобрать:
SCD41 — канал 0, SHT41 — канал 1. SDP810 остаётся напрямую на I²C2;
для его подключения через TCA установить `SDP_BUS=1`, канал 2.
Назначения шин `SCD_BUS`, `SHT_BUS`, `SDP_BUS` (1 или 2) в `board_config.h`.
Это начальные значения для платы без сохранённой топологии. После сохранения
через VisserLab используются назначения из flash, включая TCA на любой шине.
Новую прошивку нужно
записать на плату; программные тесты не подтверждают реальные измерения.

В настройках концентратора VisserLab кнопка «Сканировать I²C» ищет отвечающие
адреса 0x08…0x77 на обеих шинах: I²C1 PB6/PB7 и I²C2 PB10/PB11;
для каждого назначенного TCA9548A проверяются все восемь ветвей. Ошибка одной шины
показывается отдельно и не препятствует скану другой. По адресу выводится предположение
о модели; устройства автоматически не добавляются. Нужна прошивка с командой
I2C_SCAN_REQ (0x0090).

До подготовки опыта откройте у концентратора «Шины и подключения»: добавьте
TCA на нужную шину, нажмите «Найти и определить датчики» и добавьте найденный
датчик в стенд. Модель подтверждается корректным измерением, поиск выполняется
в фоне. В окне датчика «Применить» сохраняет подключение на плате; при удалении
из стенда можно также удалить назначение с платы. Удалять TCA следует после
удаления использующих его назначений. Ошибка I²C при отключении TCA оставляет
его в конфигурации и показывается пользователю.

CH32V303CBT6 также имеет I²C2: SCL PB10, SDA PB11. I²C1 можно переназначить
на SCL PB8, SDA PB9 (remap); это тот же I²C1, а не отдельная третья шина.
Обе шины работают на 400 кГц; каждой нужны собственные подтяжки SCL/SDA к 3,3 В.
